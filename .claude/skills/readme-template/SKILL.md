name: readme-template
description: This skill defines the base structure the user expects whenever updating or setting up a repos readme. This template is not fully comprehensive , so if a new section warrants being added confer with the user.
---


### Overview:

3-4 Sentences on what the project is and its purpose.
 - What is it trying to accomplish / what is the goal
 - is it a side project / portfolio project or for end users
 - any other key information


### Set Up Guide

How to clone the repo and set up any dependencies.

- this could have a subsection that focuses strictly on dependencies.

### Table of Contents

This section should contain the core project structures key files. Each key file gets a bullet point, hyperlinked name of the file, with a description of what it does. This should not include reference docs etc only key files.

### Project Roadmap

- What is completed
- What is a placeholder
- What is planned to be completed


### Architecture

Overview of the key components of the system or application.
Include a mermaid diagram showing the high level flow chart of the repo.


### Contributing
Short overview on how to contribute.

### Sources

Cite any key external reference sources that contributed to the project.
Include detail and the sources and what is coming out of them.


### Licensing

Licensing overview.



For how to format a readme , reference: https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/basic-writing-and-formatting-syntax
